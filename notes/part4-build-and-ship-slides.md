# 提示詞 2：請 AI 寫程式

<div class="lead">規格書你已經看過、改過。這一步只是請它開工。</div>

```
規格書我看過了，可以照這份寫。

請幫我寫成【一個單一 HTML 檔案，檔名固定叫 index.html】，
我用瀏覽器打開就能玩，不需要安裝任何東西、不需要開伺服器。

請遵守我的三條鐵律：
1. 只做一個 HTML 檔
2. 卡片資料集中放在檔案上方一個地方，加卡片不用改遊戲邏輯
3. 每個決策都要讓玩家看得到結果（做完顯示現金變化與原因）

另外請做到：
・畫面上隨時看得到：目前第幾輪、我的現金、電腦的現金
・每輪結束顯示這一輪發生什麼、現金怎麼變
・第 15 輪結束顯示結算：雙方「現金＋未到期投資估值」與輸贏
・程式碼裡的中文註解請寫清楚，我看不懂程式，但我想知道每一段在做什麼

寫完之後，請告訴我三件事：
1. 檔案要怎麼存、怎麼打開
2. 卡片資料在第幾行附近，我以後想加卡片要改哪裡
3. 有沒有哪個地方你不確定、建議我先測試
```

- 最後那三個問題是關鍵：<span class="highlight">它會告訴你「以後要改哪裡」和「它自己不確定的地方」</span>
- **檔名一定要指定 `index.html`**：等一下上架時，網址只認這個名字；存成別的名字，網頁會開出一片「404」

# 提示詞 3：東西壞了怎麼講

<div class="lead">報修不要只說「壞了」。三句話公式：我做了什麼、我以為會怎樣、實際怎樣。</div>

```
遊戲有一個問題，我描述給你聽：

【我做了什麼】
我選了護理師，玩到第 4 輪，抽到「小額投資機會」，我按了「投資」。

【我以為會怎樣】
現金應該減少投資金額，第 5 輪應該告訴我賺了還是賠了。

【實際怎樣】
現金確實減少了，但第 5 輪什麼都沒發生，一直到第 15 輪都沒有結果，
最後結算的時候那筆錢好像就消失了。

【附上截圖】
（把畫面截圖直接貼上來）

請先告訴我你認為原因是什麼、在哪一段程式，
我確認之後你再改。不要一次改很多地方。
```

- 「先講原因、我確認再改」是<span class="highlight">你在提示詞 1 學到的審核點，在除錯時一樣適用</span>
- 截圖是最省事的溝通方式：**你不用會描述畫面，直接讓它看**

# 提示詞 4：加一個很小的功能

<div class="lead">重點不是這個功能，是<b>練習「小步」的手感</b>。</div>

```
我想加一個小功能，範圍請控制在最小：

每一輪結束時，電腦對手講一句話，說明它這一輪為什麼那樣做。
例如「現金夠了，我投資」「這輪錢不夠，我先存著」。

限制：
・只加這一個功能，不要順手改別的地方
・不要改動遊戲規則與數值
・改完請給我一份「變更說明」，分成三段寫：
  1. 改了什麼（動到哪幾個地方）
  2. 為什麼這樣改
  3. 可能影響到哪裡

最後請跟我確認一件事：
這次改動有沒有可能影響到現有的計算結果？如果沒有，請說明你怎麼確定的。
```

<div class="grid">
  <div class="box red">
    <strong>「不要順手改別的地方」</strong><br>
    這句一定要寫。不寫，它很容易「順便幫你優化」
  </div>
  <div class="box blue">
    <strong>三段式變更說明</strong><br>
    就是第 75 頁那份文件的縮小版，養成習慣就對了
  </div>
</div>

# 驗收清單：怎樣算「做完了」

<div class="lead">五項全過才算。前四項現在就測，第五項要等下一頁拿到網址。</div>

- ☐ **打開就能玩**：一個檔案，點兩下就開，不用裝任何東西
- ☐ **15 輪跑得完**：從頭玩到尾，中間不會卡住、不會當掉
- ☐ **電腦對手有在動**：它真的會依現金決定投不投資，不是擺著好看
- ☐ **結算畫面正確**：雙方金額都有、輸贏判定正確、平手也處理了
- ☐ **朋友自己玩得懂**：<span class="highlight">你不在旁邊講，他也知道自己在幹嘛</span>

- 前四項你自己測得出來，**現在就測**
- **第五項只能找人**，而且要等下一頁上架拿到網址，才好把東西交到他手上——這就是第三部 Step4 的實戰
- 五項全過之前，先不要急著加**更多**功能（上一頁那個「小步」練習不算，它就是要你在驗收前先體會一次小改動）

# 上架：讓它有一個網址

<div class="lead">單一 HTML 檔傳給對方也能玩；但有了網址，你才能貼在任何地方，而且改一次大家都是新的。</div>

<div class="grid">
  <div class="box">
    <strong>① 建 Repository</strong><br>
    記得選 <b>Public</b><br>
    <i>免費版 Pages 只給公開的用</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>② 把檔案放上去</strong><br>
    Add file → Upload files<br>
    <i>第二部頁 48–49 的網頁路線</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box red">
    <strong>③ 開 Pages</strong><br>
    Settings → Pages<br>
    Branch 選 <b>main</b><br>
    <i>不是 gh-pages</i>
  </div>
</div>

- 傳檔案的缺點是**版本會散掉**：你改了第五版，朋友手上還是第二版。網址沒有這個問題
- 全程在網頁上做，**不用裝 Git、不用開終端機**——第二部頁 49 說過，那三行指令是裝了 Git 之後才用得到的，這裡用不到
- 上傳前確認檔名是 <b>index.html</b>；逐步截圖在〈把你的作品放上網：GitHub 三步驟實戰〉那一章，這裡不重複
- <span class="highlight">Branch 要選 `main`</span>：很多舊教學叫你選 `gh-pages`，那是專案有自動建置時才會有的分支，你這種直接放 HTML 的專案，選單裡沒有它是正常的

# 傳給朋友玩，收第一批回饋

<div class="lead">找 2-3 個人就好。重點不是人多，是他們沒看過你怎麼做的。</div>

<div class="grid">
  <div class="box blue">
    <strong>問這三句就夠</strong><br>
    「你卡在哪裡？」<br>
    「有沒有哪裡覺得莫名其妙？」<br>
    「玩完你知道自己為什麼贏／輸嗎？」
  </div>
  <div class="arrow">➔</div>
  <div class="box red">
    <strong>你要做的</strong><br>
    <b>閉嘴，看他操作</b><br>
    <i>想解釋的時候忍住</i><br>
    <i>那個想解釋的衝動，</i><br>
    <i>就是要修的地方</i>
  </div>
</div>

- 第三句最有價值：他答不出來，代表<span class="highlight">「決策 → 結果」這件事你還沒做到</span>
- 回饋收到之後，照第三部教的：先問「這幾個抱怨會不會是同一件事」

# 你剛剛走完的，是產品週期的主幹

<div class="lead">不是作業，不是範例。是一個真的有人能打開來玩的東西。</div>

<div class="grid">
  <div class="box">
    <strong>想法</strong><br>鐵律與規格
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>實作</strong><br>AI 寫、你審
  </div>
  <div class="arrow">➔</div>
  <div class="box">
    <strong>測試</strong><br>自己玩、找人玩
  </div>
  <div class="arrow">➔</div>
  <div class="box red">
    <strong>上線</strong><br>有網址、能分享
  </div>
</div>

- 對照第三部頁 107 的**七項**：**① 鐵律＋不做清單、② 規格書、③ 變更說明（頁 119 那份）、⑦ 一個真的能跑的東西**——這四項你已經有了
- **⑥ Step6 三條驗收**算半項：頁 120 驗了流程跑得通、陌生人玩得動，但**鐵律有沒有被破，還沒回頭對過**
- **缺兩項**：④ 四欄測試紀錄、⑤ 專案現況盤點。它們在只有一個檔案時感覺多餘，等你有第二個作品、或隔三個月回來改，就會知道為什麼要留
- 這一圈跟 FinFlow 走的是**同一圈**，只是規模不同——它到現在跑了 74 次，你跑了 1 次
- <span class="highlight">你現在缺的不是能力，是次數。</span>而次數是可以累積的

# 卡關的話：四個最常見的地方

<div class="lead">先看這裡。四個裡面通常有一個是你。</div>

| 你遇到的 | 怎麼辦 |
| :--- | :--- |
| **AI 給的檔案打不開**<br>或打開一片空白 | 把畫面截圖丟回去，加一句「打開是空白的，請檢查」。**不要自己去改程式碼**，你不需要看得懂 |
| **規格書跟我想的不一樣** | 這是好事，代表審核點有作用。逐項講哪裡不對、你要的是什麼，請它改規格書，**不要直接跳去寫程式** |
| **找不到人幫忙測試** | 家人就可以。真的找不到，就隔一天再自己玩一次——<span class="highlight">隔一天的你，比今天的你更像陌生人</span> |
| **做到一半想加東西**<br>（發生頻率最高） | 記下來，做完再說。這張清單就是你的「之後做」欄，第一部頁 21 教過怎麼分級 |

- 四個裡面最後那個最常發生，也最難忍。<span class="highlight">忍住，你才交得出第一個作品</span>
