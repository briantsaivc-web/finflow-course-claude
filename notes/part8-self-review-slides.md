# 用這套方法，審它自己

<div class="lead">第七部說「換題目，不換流程」。這一部是把那句話真的做了一次——題目換成「審一本書」，被審的就是你手上這本。</div>

| 流程位置 | 做一款遊戲 | 審這本書 |
| :--- | :--- | :--- |
| **想法** | 財商桌遊，解決什麼痛點 | 這本書教的方法，能不能拿來審它自己 |
| **規格書** | 15 輪、6 職業、怎麼算贏 | 審什麼、**不審什麼**、什麼才算一條「真」的問題 |
| **執行 ⇄ 優化** | 一輪改一個機制 | 一輪審一個部，改完、驗完，才進下一部 |
| **卡住的岔路** | 問「遊戲團隊怎麼分工」 | 問「**出版社怎麼分工**」：讀者、編輯、事實查核、通讀 |
| **交叉抓錯** | 三個 AI 互相打臉 | 三個角色互不知情，我逐條回查原文裁決 |
| **四道閘門** | 回歸測試、變更說明、備份、落地驗證 | 每批重跑檢查表、變更說明、原稿留底、渲染出來看過 |
| **成品・上線** | 別人打得開就能玩 | 改完的書，陌生人照順序讀得下去 |

- **七格一格都沒有換**，換掉的只有<span class="highlight">每一格「怎麼算做好」</span>——跟第七部說的一樣
- 全部發生在書寫完之後：**七輪、17 份 AI 獨立審查報告**。這一部就是那個過程的紀錄

# 換的不是方法，是證據長什麼樣

<div class="lead">第六部的三條底線全部保留：獨立審、附證據、分歧由人裁。第八部新增的不是第二套交叉抓錯，而是換一種證據。</div>

| | 第六部：審程式 | 第八部：審文件 |
| :--- | :--- | :--- |
| 審的是 | 可以執行的行為與機制 | 文字主張、結構與一致性 |
| **主要硬證據** | **實跑、測試、原始碼** | **原文、來源、算式、索引、腳本** |
| 判不動的部分 | 由人裁決 | 由人裁決 |
| 失敗長怎樣 | 修改碼看起來對，跑下去炸 | 引用一個**不存在的頁碼**，你不查就信了 |

- 第六部**不是只有「跑一次」**：它的反向質詢提示詞（頁 142）也要求「逐條核對原始碼，附行數」——那已經是文件式的核對
- 差別在於**手上有什麼可以當硬證據**。程式有實跑（頁 139）；一份報告沒有，就只剩原文、來源與算式
- 你的報告、企劃、合約、簡報——<span class="highlight">全都屬於右邊那一欄</span>。這才是大多數人的實際處境

# 實證紀錄：這次審書怎麼跑

<div class="lead">這<b>不是另一套七步流程</b>（那個在第六部頁 141）。這是把第七部的方法用在這本書上時，實際發生的七個動作。</div>

| | 做了什麼 | 為什麼 |
| ---: | :--- | :--- |
| ① | 決定拿這本書當題目 | 要檢驗這套流程能不能跨到別的工作，最硬的做法就是**拿它審自己** |
| ② | **請 AI 幫我寫審查用的 prompt** | 我知道要審什麼，但不知道怎麼把它講成 AI 聽得懂的指令 |
| ③ | 起手 2 個 AI × 2 個角色，四份回饋 | 直覺上「越多越好」——但這是直覺，不是結論 |
| ④ | 量了之後改成<b>每個角色只用 1 個 AI</b> | 角色數量不變，是同一個角色不再找兩家做。下一頁講為什麼 |
| ⑤ | **分段審**：一部一輪，過程中回頭改 prompt | 每一輪漏掉的東西，都變成下一輪 prompt 的新規則 |
| ⑥ | 全部審完之後，再加**全書通讀**與**懷疑論者** | 部內審查有一整類問題結構性看不見 |
| ⑦ | 把整個過程寫成這一部 | 不寫下來，下次還是從頭摸索 |

- 第 ⑤ 步是整套的引擎：<span class="highlight">prompt 不是一次寫好的，是被漏網的問題一條一條逼出來的</span>

# 實驗：角色重要，還是模型重要？

<div class="lead">兩個 AI 各演兩個角色，就是四份回饋——聽起來一定比較好。但這是直覺。所以量了一次。</div>

| 比較對 | 變動的是 | 兩份重疊率 |
| :--- | :--- | ---: |
| 同一個 AI，讀者 ↔ 編輯 | **角色** | 6.5% |
| 另一個 AI，讀者 ↔ 編輯 | **角色** | 26% |
| 兩個 AI，都演讀者 | **模型** | **45%** |
| 兩個 AI，都演編輯 | **模型** | **44%** |

- 換角色時兩份的重疊只有 **6.5% 與 26%**；換模型時是 **45% 與 44%**。<span class="highlight">在這次的樣本裡，角色差異帶來的新東西，明顯多過換模型</span>
- 所以配置改成**每個角色只用 1 個 AI**：角色數量不變，是同一個角色不再找兩家做
- **但這是有代價的取捨，不是「模型不重要」**：兩個「讀者」雖然重疊 45%，各自獨得的真問題卻一樣多——其中一個抓到「代碼」是中國大陸用語、**影響全課 23 處跨 9 個檔**，另一個完全沒看到
- <b>誠實講清楚：省一半成本，代價是可能漏掉單一模型的盲點。</b>資源有限時先加角色；<span class="highlight">但關鍵的那一章，值得讓同一個角色再找第二家看一次</span>

# 三條車道：它們問的是不同的問題

<div class="lead">角色不是換個稱呼，是換一個「你要它拿什麼眼睛看」。</div>

| 角色 | 它問的那句話 | 它專門抓的 |
| :--- | :--- | :--- |
| **讀者** | 「我看不懂」 | 術語、跳步、前面沒教就用了的東西 |
| **編輯** | 「這兩處對不起來」 | 前後矛盾、承諾沒兌現、口徑不一 |
| **懷疑論者** | <span class="highlight">「這是真的嗎」</span> | 沒有依據的數字、把個案寫成通則 |

- 前六輪只有讀者與編輯。加上懷疑論者那一輪，它回報 **41 條可查證的宣稱，26 條書裡沒有依據**——<b>前六輪一條都沒碰過</b>
- 它抓到最重的一條，是書裡自己批評別人「無法回查」的那一頁，**自己的數字同樣無法回查**
- **為什麼漏了那麼久**：讀者不會問真假，編輯只比對書裡兩處——<span class="highlight">沒有人負責問「書外面的世界同不同意」</span>

# 什麼時候要開新視窗？

<div class="lead">不是每次都要開新的，但有一種情況一定要。</div>

<div class="grid">
  <div class="box blue">
    <strong>同一個層次：風險較低</strong><br>
    同一個對話串重複貼不同章節<br>
    <i>這次沒觀察到明顯干擾</i><br>
    <b>提示詞每次重帶背景，<br>可能是原因</b>
  </div>
  <div class="arrow">➔</div>
  <div class="box red">
    <strong>換一個層次：一定要開新的</strong><br>
    從「審一個部」換成「通讀全書」<br>
    <i>續用會被前面的部內結論綁住</i><br>
    <b>它會繼續挑細節，看不見跨部</b>
  </div>
</div>

- 判準：<span class="highlight">你換的是「材料」，風險較低；你換的是「用什麼眼睛看」，一定要新視窗</span>
- **但左邊那格只是一次事後觀察，不足以推翻「新章節就開新視窗」這個預設**。要徹底避開錨定，每一章各開一個最穩
- 同一輪的不同角色，沿用第六部的盲審原則：**各自新視窗、互不知情**——避免第二個角色被第一個的結論帶著走

# 能用程式查的，不要花 AI 的注意力

<div class="lead">AI 很會讀，但不會數。這兩件事要分開派工。</div>

<div class="grid">
  <div class="box red">
    <strong>數數出錯的三次</strong><br>
    <b>AI 兩次</b>：把 58 張卡數成 46 張<br>（漏掉一整包 12 張）；<br>把檔案行號當成頁碼<br>
    <b>我自己一次</b>：對照一張七項清單，<br>寫成「五項做了、三項沒做」<br>（5＋3＝8，不是 7）
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>改派給一支小程式</strong><br>
    每一頁的頁碼與標題<br>
    每一處「頁 N」指不指得到<br>
    該用的詞有沒有被寫成別的<br>
    <i>一條指令重跑，別人也跑得出同樣結果</i>
  </div>
</div>

- 它產出一份**全書清單**（每一頁、每一處引用、每一個該統一的詞），跟著書一起存檔。每改一批就重跑、比對差異——<span class="highlight">改了前面弄壞後面，就跑不掉</span>
- 它第一次跑就抓到兩處：一個統一過的用語漏了首頁沒改、一個過期兩批的更新日期
- **判準**：只要「數得出來、比得出來」的，就別問 AI。把 AI 的注意力留給它真正強的——讀懂意思

# 讓 AI 不亂編的兩條規則

<div class="lead">加了兩句話之後，這七輪沒有再出現捏造引述。</div>

<div class="grid">
  <div class="box red">
    <strong>之前發生過什麼</strong><br>
    AI 交出除錯報告<br>
    <b>引用了一支不存在的測試腳本</b><br>
    <i>還寫「已在沙盒實際執行」</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>prompt 裡加的兩句</strong><br>
    ① <b>引述必須是原文，一字不改</b><br>
    　 引不出原文的就不要寫<br>
    ② <b>這份報告會交給另一位<br>　 審查者逐條覆驗</b>
  </div>
</div>

- 加上之後：**七輪、17 份報告，0 筆捏造引述**。只出過一次位置引用錯誤（把行號當頁碼）
- **這是前後觀察，不是對照實驗**：我沒有另外跑一批「不加這兩句」的來比，所以不能斷定就是這兩句造成的。<span class="highlight">但值得你加上去，成本是零</span>
- 而且**告知不等於免查**。我還是每一條都回查原檔——差別是回查後幾乎都對得上，成本低很多

# 工具擋住的時候：換入口，不要卡在那裡

<div class="lead">同一家的模型，裝在不同的殼裡，能做的事不一樣。</div>

<div class="grid">
  <div class="box red">
    <strong>網頁版讀不到</strong><br>
    貼上原始檔網址<br>
    回「網路連線存取限制」<br>
    <i>要我把整份內容貼進對話框</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>換一個殼就通了</strong><br>
    同一家的模型，<br>換成裝在開發工具裡的版本<br>
    <b>直接抓得到，照樣把報告做完</b>
  </div>
</div>

- **為什麼？我不知道**，那是對方的設定，我查不到——這一頁只寫我實際看到的事（**一次**，不是統計）
- 但可以帶走一條操作原則：<span class="highlight">不要把「這個介面做不到」直接推成「這個 AI 做不到」</span>。先換一個入口確認，再下結論
- 附帶一提：那一輪（事實查核）用的是**便宜的快速型號**，照樣把 41 條宣稱比對完。至少表示<b>這個任務不一定需要高階型號</b>——但不能因此推論模型等級普遍不重要

# 成績單：它抓到什麼，又漏掉什麼

<div class="lead">只寫成功案例的方法論不值得信。這一頁把它抓到我的那幾條也列出來。</div>

**它抓到最重的一條**：書裡教「先要規格，再要程式」，但**全書第一句可以直接複製的指令，就是直接叫 AI 寫程式**。兩頁各自都沒問題，合起來才是錯的。

| 它抓到作者的 | 原本寫的 | 實際是 |
| :--- | :--- | :--- |
| 一個關鍵數字 | 第六部說「實跑 24,000 局」 | 沒有腳本、沒有算式，**跟它自己批評的那份報告一樣無法回查** |
| 一個版本編號 | 「第 26 版才學會」 | 一次施工叫一「批」，一次改版叫一「版」，**一批可能交出好幾版**。那時早就超過 40 版，指的其實是**第 26 批** |
| 一段時間 | 「五天」 | 六個日曆日（書裡另一頁自己寫了六天） |
| 一段算術 | 對照七項，「五項走過、三項沒做」 | 5＋3＝**8**，不是 7 |

- **它漏掉的**：前六輪、14 份部內報告，<span class="highlight">沒有一份看見跨部矛盾</span>——因為沒有人被指派去讀完整本
- 所以第七輪補了三份：**通讀上半、通讀下半、懷疑論者**（14＋3＝17）。**很多漏掉的問題，關鍵往往不是 AI 不會，是沒有人被派去看那個維度**
- **四份可以直接複製的完整提示詞**（讀者／編輯／懷疑論者／通讀），在圖文版〈用這套方法審它自己〉
