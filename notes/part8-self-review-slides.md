# 用這套方法，審它自己

<div class="lead">第七部說「換題目，不換流程」。這一部是把那句話真的做了一次——題目換成「審一本書」，被審的就是你手上這本。</div>

| 流程位置 | 做一款遊戲 | 審這本書 |
| :--- | :--- | :--- |
| **想法** | 財商桌遊，解決什麼痛點 | 這本書教的方法，能不能拿來審它自己 |
| **規格書** | 15 輪、6 職業、怎麼算贏 | 審什麼、**不審什麼**、什麼才算一條「真」的問題 |
| **執行 ⇄ 優化** | 一輪改一個機制 | 一輪審一個部，改完、驗完，才進下一部 |
| **交叉抓錯** | 三個 AI 互相打臉 | 三個角色互不知情，我逐條回查原文裁決 |
| **四道閘門** | 回歸測試、變更說明、備份、落地驗證 | 引述回查、每批留指紋、台帳腳本、渲染確認 |
| **成品・上線** | 別人打得開就能玩 | 改完的書，陌生人照順序讀得下去 |

- <span class="highlight">一格都沒有換</span>——換掉的只有「怎麼算做好」那一欄，跟第七部說的一樣
- 全部發生在書寫完之後：**七輪、17 份外部報告**。這一部就是那個過程的紀錄

# 沒有「實跑」可以當裁判的時候

<div class="lead">第六部靠實跑分勝負：程式跑一次，誰對誰錯當場見真章。但多數工作沒有這種奢侈品。</div>

| | 第六部：審程式 | 第八部：審文件 |
| :--- | :--- | :--- |
| 審的是 | 它**會不會跑** | 它**講得對不對** |
| 有沒有客觀真值 | **有**——跑一次就知道 | **沒有**——沒得跑 |
| 誰當裁判 | 實跑結果（頁 139） | 只能靠**角色分工 ＋ 逐條回查原文** |
| 失敗長怎樣 | 修改碼看起來對，跑下去炸 | 引用一個**不存在的頁碼**，你不查就信了 |

- 你的報告、企劃、合約、簡報——<span class="highlight">全都屬於右邊那一欄</span>。這才是大多數人的實際處境
- 沒有真值可以裁決的時候，**代替品是「讓不同角色各自看，然後每一條都要拿出原文」**
- 這一部教的就是右邊那一欄怎麼做

# 七個步驟：這一輪實際怎麼跑的

<div class="lead">從「想驗證這套方法通不通用」到「把過程寫回書裡」。</div>

| | 做了什麼 | 為什麼 |
| ---: | :--- | :--- |
| ① | 決定拿這本書當題目 | 要證明流程通用，最硬的驗證就是**拿它審自己** |
| ② | **請 AI 幫我寫審查用的 prompt** | 我知道要審什麼，但不知道怎麼把它講成 AI 聽得懂的指令 |
| ③ | 起手 2 個 AI × 2 個角色，四份回饋 | 直覺上「越多越好」——但這是直覺，不是結論 |
| ④ | 量了之後改成 **1 個 AI・1 個角色** | 下一頁講量出了什麼 |
| ⑤ | **分段審**：一部一輪，過程中回頭改 prompt | 每一輪漏掉的東西，都變成下一輪 prompt 的新規則 |
| ⑥ | 全部審完之後，再加**全書通讀**與**懷疑論者** | 部內審查有一整類問題結構性看不見 |
| ⑦ | 把整個過程寫成這一部 | 不寫下來，下次還是從頭摸索 |

- 第 ⑤ 步是整套的引擎：<span class="highlight">prompt 不是一次寫好的，是被漏網的問題一條一條逼出來的</span>

# 實驗：角色重要，還是模型重要？

<div class="lead">兩個 AI 各演兩個角色，就是四份回饋——聽起來一定比較好。但這是直覺。所以量了一次。</div>

| 比較對 | 變動的是 | 兩份重疊率 |
| :--- | :--- | ---: |
| 同一個 AI，讀者 ↔ 編輯 | **角色** | 6.5% |
| 另一個 AI，讀者 ↔ 編輯 | **角色** | 26% |
| 兩個 AI，都演讀者 | **模型** | **45%** |
| 兩個 AI，都演編輯 | **模型** | **44%** |

- **換模型，一半以上是重工；換角色，八成以上是新東西。**<span class="highlight">角色決定你會找到什麼，模型幾乎不影響</span>
- 所以配置從 2 AI × 2 角色改成 <b>1 AI・1 角色</b>：**要幾個角色，就開幾個視窗**，不用同一個角色找兩家做
- **但重疊率只是診斷，不是砍格子的理由**：兩個「讀者」重疊 45%，各自獨得的真問題卻一樣多——其中一個抓到「代碼」是中國大陸用語、影響全課 22 處，另一個完全沒看到

# 三條車道：它們問的是不同的問題

<div class="lead">角色不是換個稱呼，是換一個「你要它拿什麼眼睛看」。</div>

| 角色 | 它問的那句話 | 它專門抓的 |
| :--- | :--- | :--- |
| **讀者** | 「我看不懂」 | 術語、跳步、前面沒教就用了的東西 |
| **編輯** | 「這兩處對不起來」 | 前後矛盾、承諾沒兌現、口徑不一 |
| **懷疑論者** | <span class="highlight">「這是真的嗎」</span> | 沒有依據的數字、把個案寫成通則 |

- 前六輪只有讀者與編輯。加上懷疑論者那一輪，它回報 **41 條可查證的宣稱，26 條書裡沒有依據**——<b>前六輪一條都沒碰過</b>
- 它抓到最重的一條，是書裡自己批評別人「無法回查」的那一頁，**自己的數字同樣無法回查**
- **為什麼漏了那麼久**：讀者不會問真假，編輯只比對書裡兩處——<span class="highlight">沒有人負責問「書外面的世界同不同意」</span>

# 什麼時候要開新視窗？

<div class="lead">不是每次都要開新的，但有一種情況一定要。</div>

<div class="grid">
  <div class="box blue">
    <strong>同一個層次：可以續用</strong><br>
    同一個對話串重複貼不同章節<br>
    <i>實測 0 污染</i><br>
    <b>因為 prompt 自己帶齊了背景</b>
  </div>
  <div class="arrow">➔</div>
  <div class="box red">
    <strong>換一個層次：一定要開新的</strong><br>
    從「審一個部」換成「通讀全書」<br>
    <i>續用會被前面的部內結論綁住</i><br>
    <b>它會繼續挑細節，看不見跨部</b>
  </div>
</div>

- 這件事的判準很簡單：<span class="highlight">你換的是「材料」，續用沒差；你換的是「用什麼眼睛看」，就要新視窗</span>
- 同一輪的不同角色，也**一律各自開新視窗、互不知情**——否則第二個角色會順著第一個的結論走，這就退化成一份報告

# 能用程式查的，不要花 AI 的注意力

<div class="lead">AI 很會讀，但不會數。這兩件事要分開派工。</div>

<div class="grid">
  <div class="box red">
    <strong>AI 數數出錯的三次</strong><br>
    <i>把 58 張卡數成 46 張</i><br>
    （漏掉一整包 12 張）<br>
    <i>把檔案行號當成頁碼</i><br>
    <i>我自己把 5＋3 對照成 7 項</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>改派給一支腳本</strong><br>
    每一頁的頁碼與標題<br>
    每一處「頁 N」指不指得到<br>
    正規用語 vs 不該出現的變體<br>
    <i>一條指令重跑，結果可複驗</i>
  </div>
</div>

- 這支腳本產出一份**台帳**，進版控。每改一批就重跑一次、比對差異——<span class="highlight">跨部回歸就跑不掉</span>
- 它第一次跑就抓到兩處：一個統一過的用語漏了首頁、一個過期兩批的更新日期
- **判準**：只要「數得出來、比得出來」的，就別問 AI。把 AI 的注意力留給它真正強的——讀懂意思

# 讓 AI 不亂編的兩條規則

<div class="lead">同一個模型，加了兩句話之後，七輪沒有再捏造過一次。</div>

<div class="grid">
  <div class="box red">
    <strong>之前發生過什麼</strong><br>
    AI 交出除錯報告<br>
    <b>引用了一支不存在的測試腳本</b><br>
    <i>還寫「已在沙盒實際執行」</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>prompt 裡加的兩句</strong><br>
    ① <b>引述必須是原文，一字不改</b><br>
    　 引不出原文的就不要寫<br>
    ② <b>這份報告會交給另一位<br>　 審查者逐條覆驗</b>
  </div>
</div>

- 加上之後：**七輪、17 份報告，0 筆捏造引述**。只出過一次位置引用錯誤（把行號當頁碼）
- 為什麼有效：<span class="highlight">先告知會被查，品質就上去了</span>——這跟人一模一樣
- 但**告知不等於免查**。我還是每一條都回查原檔——差別是回查後幾乎都對得上，成本低很多

# 工具擋住的時候：換入口，不要卡在那裡

<div class="lead">同一家的模型，裝在不同的殼裡，能做的事不一樣。</div>

<div class="grid">
  <div class="box red">
    <strong>網頁版讀不到</strong><br>
    貼上原始檔網址<br>
    回「網路連線存取限制」<br>
    <i>要我把整份內容貼進對話框</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box blue">
    <strong>換一個殼就通了</strong><br>
    同一家的模型，<br>裝在開發工具裡<br>
    <b>直接抓得到，照樣把報告做完</b>
  </div>
</div>

- **為什麼？我不知道**，那是對方的設定，我查不到——這一頁只寫我實際看到的事
- 所以「某某 AI 做不到」這句話通常是錯的。正確的說法是<span class="highlight">「某某 AI 的**這個介面**做不到」</span>
- 附帶一個數據點：那一輪用的是**便宜的快速型號**，照樣把事實查核做完了——再一次印證<b>決定品質的是角色，不是模型等級</b>

# 成績單：它抓到什麼，又漏掉什麼

<div class="lead">只寫成功案例的方法論不值得信。這一頁把它抓到我的那幾條也列出來。</div>

**它抓到最重的一條**：書裡教「先要規格，再要程式」，但**全書第一句可以直接複製的指令，就是直接叫 AI 寫程式**。兩頁各自都沒問題，合起來才是錯的。

| 它抓到作者的 | 原本寫的 | 實際是 |
| :--- | :--- | :--- |
| 一個關鍵數字 | 「實跑 24,000 局」 | 沒有腳本、沒有算式，**跟被它批評的那份報告一樣無法回查** |
| 一個版本編號 | 「第 26 版才學會」 | 那時早就超過 40 版，它指的是**第 26 批** |
| 一段時間 | 「五天」 | 六個日曆日（書裡另一頁自己寫了六天） |
| 一段算術 | 對照七項，「五項走過、三項沒做」 | 5＋3＝**8**，不是 7 |

- **它漏掉的**：六輪、14 份部內報告，<span class="highlight">沒有一份看見跨部矛盾</span>——因為沒有人被指派去讀完整本
- 所以最後補了通讀與懷疑論者兩條車道。**你缺的那一類問題，通常不是 AI 不會，是沒有人被派去看那個維度**
