# Step6：什麼時候可以說「能分享了」？

<div class="lead">判斷標準不是「我做完了嗎」，是<b>「我可以離開房間了嗎」</b>。</div>

<div class="grid">
  <div class="box">
    <strong>① 鐵律都沒被違反</strong><br>
    那三條你一開始寫下的<br>
    <i>回頭對一次</i>
  </div>
  <div class="box blue">
    <strong>② 核心流程玩得通</strong><br>
    從開始到結束跑一遍<br>
    <i>中間不會卡死</i>
  </div>
  <div class="box red">
    <strong>③ 陌生人自己玩得動</strong><br>
    你不用坐在旁邊解釋<br>
    <i>這條最難，也最重要</i>
  </div>
</div>

- 第 ③ 條是唯一的真考驗：<span class="highlight">如果每次都要你在旁邊講，那說明書就是你本人</span>
- 三條同時成立，才叫「能分享」。不是三缺一，是三缺零
- **怎麼給出去**：單一 HTML 檔可以直接傳給對方用瀏覽器打開；想要一個網址，用 GitHub Pages（工具在第二部頁 53，**上架的點擊步驟在第四部頁 121**）

# 案例：有四期，一個新功能都沒做

<div class="lead">第 17～20 批做的全是「讓別人能自己上手」的收尾工程。</div>

| 第幾批 | 做了什麼 | 為了解決 |
| :--- | :--- | :--- |
| 17 | 主畫面三欄重整 | 操作區要往下滑才按得到；四人的卡片排成 3＋1 很醜 |
| 18 | 通知分類 | 訊息太吵，重要的被淹沒 |
| 19 | 三人實測，5 筆回報收斂成 3 個問題 | 自己測不出來的那些 |
| 20 | 互動教學 | 新玩家不用問人就會玩 |

- 這四批的共同點：<span class="highlight">功能一個都沒加，但產品從「我能玩」變成「別人能玩」</span>
- 沒有這四批，前面幾十批做的東西沒有人拿得起來用
- 收尾不是終點：這一版能分享之後，又繼續做了二十幾批

# 收尾階段，要換一顆腦袋

<div class="lead">「知識的詛咒」：你一旦懂了，就再也想不起來不懂是什麼感覺。</div>

<div class="grid">
  <div class="box">
    <strong>開發階段你在問</strong><br>
    「這個功能<br>做不做得出來？」<br>
    <i>看的是可行性</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box red">
    <strong>收尾階段要問</strong><br>
    「一個完全不懂的人<br>能不能自己搞懂？」<br>
    <i>看的是別人的視角</i>
  </div>
</div>

- 這兩個問題會給你**完全相反的待辦清單**，所以不能同時做
- **什麼時候該換腦袋**：核心流程從頭到尾跑得通、而且你決定<b>這一版不再加新功能</b>的那一刻
- 實務上最有效的解法很簡單：**找一個真的不懂的人來玩，然後閉嘴看他操作**

# 回顧：整個第三部在講什麼

<div class="lead">頁 85b 那張表再看一次。<b>一個起點＋六個步驟</b>，從鐵律開始，繞一圈回到鐵律。</div>

| | 步驟 | 跳過這一步的下場 |
| :--- | :--- | :--- |
| **起點** | Step0 寫鐵律與 MVP 清單 | 一開始就想做完整版 |
| ① | Step1 先要規格書，你審核 | 直接要程式，錯了才發現 |
| ② | Step2 拿到程式先玩過 | 沒玩就說完成 |
| ③ | Step3 小步快跑疊代 | 一次做太多，壞了找不到 |
| ④ | Step4 找人測試 | 你測不出自己的 bug |
| — | **選修** 多人連線 | 不需要卻做了，白花兩週 |
| ⑤ | **Step5** 專案管理不出事 | 知識庫爆掉、文件跟程式對不上 |
| ⑥ | **Step6** 判斷能不能分享 | 自己覺得好就上線 |

- 走到 ⑥ 之後不是結束，是<span class="highlight">帶著新的想法回到 Step0，開始下一輪</span>

# 三個最常被問的問題

<div class="lead">先回答，免得你卡在這裡不敢動手。</div>

<div class="grid">
  <div class="box">
    <strong>Q：一定要照順序走完<br>Step1～Step6 嗎？</strong><br>
    多人連線是選修；Step4 找不到人<br>可以<b>暫緩</b>，但宣稱「能分享」<br>之前一定要補測<br>
    <i>Step1、Step2 不要跳</i>
  </div>
  <div class="box blue">
    <strong>Q：卡在某一步很久怎麼辦？</strong><br>
    把那一步再切小一點<br>
    <i>卡住通常是因為那一步太大</i>
  </div>
  <div class="box red">
    <strong>Q：找不到人幫忙測試？</strong><br>
    家人朋友就可以<br>
    重點不是他懂不懂，<br>
    <i>是他沒看過你怎麼做的</i>
  </div>
</div>

- 補充一句：<span class="highlight">Step1 跳過的代價最大</span>——沒有規格書，你就沒有審核點，只能等程式出來才發現方向錯
- Step1、Step2 的具體指令，<b>第四部會一句一句給你</b>

# 走完這個流程，你手上該有的東西

<div class="lead">第三部是<b>看別人怎麼做</b>；第四部才輪到你動手。這是到時候的對照清單。</div>

- ☐ **一份鐵律＋一張 MVP 清單**：三條原則，加上「這一版不做什麼」
- ☐ **至少一份規格書**：AI 生的，你逐項看過並改過
- ☐ **一串變更說明**：每次交付一份，含「未預期發現」
- ☐ **一份測試紀錄**：別人玩過之後，記下操作、預期、實際與問題
- ☐ **一次現況盤點**：文件說的，跟程式裡實際有的，對過一次帳
- ☐ **Step6 三條驗收過關**：鐵律沒破、流程跑得通、陌生人自己玩得動
- ☐ **一個真的能跑的東西**：不是投影片，是可以打開來玩的

- 前六項是過程，最後一項是結果。<span class="highlight">但真正讓你做得出最後一項的，是前六項</span>
