# 小步快跑：一次只做一個小主題

<div class="lead">怎麼吃掉一頭大象？<b>一次一口。</b></div>

<div class="grid">
  <div class="box red">
    <strong>一次做一大批</strong><br>
    做兩週才第一次打開來玩<br>
    <i>壞了不知道是哪一項害的</i>
  </div>
  <div class="box blue">
    <strong>小步疊代</strong><br>
    每一步都短，每一步都驗收<br>
    <i>壞了範圍就那麼大，好找</i>
  </div>
</div>

- 小步真正的好處不是「比較快」，是<span class="highlight">出問題時範圍小</span>
- 你不會寫程式，所以更需要這個——你唯一能判斷的是「這次改的東西壞了沒」

# 案例：六個日曆日，49 份變更說明

<div class="lead">「不積跬步，無以至千里。」——荀子《勸學》</div>

| 日期 | 交付份數 | 那天在做什麼 |
| :--- | :--- | :--- |
| 8/25（深夜開工） | 2 | 一期、二三期：把規則跑起來 |
| 8/26 | 5 | 自由圈、主畫面方案丙、體驗適配、實測回饋 |
| 8/27 | 10 | 利率通膨、商城轉介、**多人連線**與四輪實測修訂 |
| 8/28 | **14** | 內容擴充、平衡、學習系統、成就、電腦對手 |
| 8/29 | 10 | 怪符號根治、自動記帳、版面重整、股價模型 |
| 8/30 | 8 | 修好卡死不能繼續的狀況、三欄重整、三人實測、互動教學 |

- 沒有哪一天是「做一個大功能」。<span class="highlight">最多的那天做了 14 件小事</span>
- 跬步就是半步。這六天沒有哪一步是大步，但走到了很遠的地方
- 而且沒有停：從第一版到今天累計 <b>74 份</b>變更說明，版號 v1.0 → <b>v2.52.0</b>
- <b>一份變更說明＝一個版號</b>，所以後面說「74 版」跟這裡是同一件事
- **別跟「批」搞混**：一批是一次施工，一批可能交出好幾份變更說明。上面六天是**第 1～20 批**、49 份；頁 6 的 S 編號講的是批，不是版號

# 「變更說明」怎麼寫：三段就夠

<div class="lead">好記性不如爛筆頭——而且這支筆是寫給<b>半年後的自己</b>的。</div>

<div class="grid">
  <div class="box">
    <strong>① 這一版做了什麼</strong><br>
    條列，一項一行<br>
    <i>附上版本號與日期</i>
  </div>
  <div class="box blue">
    <strong>② 為什麼這樣做</strong><br>
    當時的取捨與依據<br>
    <i>「依你的手繪配置圖」也算</i>
  </div>
  <div class="box red">
    <strong>③ 未預期發現</strong><br>
    做的時候才發現的意外<br>
    <i>包括「我原本想錯了」</i>
  </div>
</div>

<b>寫在哪裡？</b>最省事：貼在 GitHub 每次 Commit 的說明欄；內容長就另存一個 `變更記錄.md` 放同一個資料夾。

- 第三段是最容易被省略、也最有價值的一段。FinFlow 每一份變更說明都有它
- 它逼你誠實：<span class="highlight">寫不出「未預期發現」，通常是你沒仔細看</span>

# 冰山一角：玩家看到的，只是水面上那一塊

<div class="lead">功能做完只是浮出水面的一角。水面下那 90%，是反覆調畫面、調卡片的時間。</div>

<div class="grid">
  <div class="box">
    <strong>視覺呈現</strong><br>
    好不好看是其次<br>
    <i>看不看得懂才是重點</i>
  </div>
  <div class="box blue">
    <strong>功能怎麼擺</strong><br>
    哪顆按鈕放哪裡<br>
    <i>常用的要按得到、不用捲</i>
  </div>
  <div class="box red">
    <strong>資訊怎麼揭露</strong><br>
    新手看到的畫面<br>
    <i>應該比老手簡單</i>
  </div>
</div>

- 第三個最容易被忽略：**同一個畫面，對新手和老手可以長得不一樣**
- 心理準備先給你：<span class="highlight">「做功能」跟「調畫面」的時間，後者往往比你想的多得多</span>

# 案例：同一個盤面，改了四次版

<div class="lead">從 8/26 到 8/30，五天之內。這還只是畫面的其中一塊。</div>

| 版本 | 日期 | 這一次改了什麼 |
| :--- | :--- | :--- |
| 五期・方案丙 | 8/26 | 依手繪配置圖，改成上下**分離雙環**（原本是同心圓） |
| S14a v2.16.0 | 8/29 | 三欄改等寬，輪盤壓到左欄上半，實測占畫面 16.7% |
| S14a v2.16.1 | 8/30 | 格子原本沿邊平均分佈、四角特別擠，改成**規整的方格環** |
| S17 v2.22.0 | 8/30 | 三欄重整；中央那疊改用<b>固定座標對齊</b>，不再用畫面百分比 |

- v2.16.1 那次特別值得看：**只換畫法，遊戲規則一行都沒動**——怎麼證明？見<b>第 81 頁</b>
- 四次改版沒有一次是「重做」，每次都只動一塊。這就是冰山水面下的樣子

# 技巧一：畫給它看，不要用講的

<div class="lead">一圖勝千言——這句話在跟 AI 描述版面時，是字面上的意思。</div>

<div class="grid">
  <div class="box">
    <strong>手繪草圖</strong><br>
    方框＋箭頭＋幾個字<br>
    <i>拍照丟給它就好</i>
  </div>
  <div class="box blue">
    <strong>Excel 拉格子</strong><br>
    儲存格合併一下當版面<br>
    <i>截圖丟給它</i>
  </div>
  <div class="arrow">➔</div>
  <div class="box red">
    <strong>逐項核對</strong><br>
    做出來之後<br>
    <i>一格一格對回你的圖</i>
  </div>
</div>

- FinFlow 好幾次版面決策都是這樣做的——變更說明裡直接寫著「依使用者手繪配置圖」「你的 Excel」
- 醜沒關係。<span class="highlight">草圖的價值在位置關係，不在美觀</span>

# 技巧三：要求它證明「數字沒被動到」

<div class="lead">「信任，但要查證。」改畫面最大的風險，是順手改到規則而你看不出來。</div>

<div class="box blue">
<strong>這句話可以直接複製</strong><br><br>
「請你證明這次改動<b>只有畫面變了</b>，遊戲規則的數字都沒有變。<br>
請用<b>完全相同的亂數種子與起始條件</b>，改動前後各跑一批模擬、逐局比對，把結果告訴我。」
</div>

- FinFlow 真的做過：改版面前後各跑 **500 局**，逐局比對現金、淨值、被動收入、支出、資產負債筆數、破產、夢想進度等十幾個欄位
- 結果寫在變更說明裡：<span class="highlight">500 局裡有 0 局不一樣</span>——完全一致
- 你不用看得懂那些欄位。你只需要看得懂「0／500」這個數字

# 案例：畫面跟著玩家的熟練度長大

<div class="lead">記帳是這款遊戲的教育核心，所以它有三個難度等級。</div>

<div class="grid">
  <div class="box">
    <strong>等級 1・全自動</strong><br>
    系統直接記<br>
    畫面高亮哪幾格變了<br>
    <i>新手先看懂帳怎麼動</i>
  </div>
  <div class="box blue">
    <strong>等級 2・分類確認</strong><br>
    系統算好金額但藏起科目<br>
    你把卡片拖到對的象限<br>
    <i>預設等級</i>
  </div>
  <div class="box red">
    <strong>等級 3・自己記＋稽核</strong><br>
    只給你交易敘述<br>
    發薪日系統跟你對帳<br>
    <i>對不起來會扣一點</i>
  </div>
</div>

- 一開始的設計是<b>解鎖不等於強制開啟</b>：達標只是「可以改成自動」，開不開你自己決定
- 後來實測覺得每次都問太煩，<span class="highlight">改成練熟當下直接幫你接手，想練再自己關掉</span>——連這種設計決定都會被自己推翻，這很正常

# 兩個真實的 UI 坑

<div class="lead">有個老比喻：<b>手指著月亮，別盯著手指看。</b>這兩個坑都是盯著手指。</div>

<div class="grid">
  <div class="box red">
    <strong>坑一：把倍率寫死</strong><br>
    畫面在大螢幕會自動放大 1.12 倍<br>
    程式量到的位置含放大、寫回去的不含<br>
    <i>結果元件整個大 12%、位置偏掉</i>
  </div>
  <div class="box red">
    <strong>坑二：測試驗錯東西</strong><br>
    要驗的畫面外面包了一層<br>
    測試抓到的是外包裝不是本體<br>
    <i>把功能刪掉，測試照樣通過</i>
  </div>
</div>

- 坑一盯的是「數字」，月亮是「畫面實際長怎樣」；坑二盯的是「測試有沒有綠燈」，月亮是「功能真的還在嗎」
- 兩個修法都一樣：**換一種方式，直接去看月亮**——量出來、真的畫一次
- 共通教訓：<span class="highlight">「感覺應該對」不算驗證</span>

# 你的 UI 調整工具箱

<div class="lead">前面三個技巧之外，再給三個馬上能用的做法，不用學任何新軟體。</div>

<div class="grid">
  <div class="box">
    <strong>① 草稿用手邊的</strong><br>
    紙筆拍照、或 Excel 拉格子<br>
    <i>不用學設計軟體</i>
  </div>
  <div class="box blue">
    <strong>② 截圖給它看</strong><br>
    「現在長這樣（附圖），<br>我想把這塊移到下面」<br>
    <i>比純文字準得多</i>
  </div>
  <div class="box red">
    <strong>③ 先能用再好看</strong><br>
    順序不要顛倒<br>
    <i>好看的不能用，等於沒做</i>
  </div>
</div>

- 最後提醒一次：每次改畫面，都順口問一句「數字有沒有被動到」（第 81 頁那句話）
